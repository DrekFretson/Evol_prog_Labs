# Отчёт по лабораторной работе №2

## 1. Постановка задачи

Индивидуальный вариант:

```text
V = 19
```

Задача:

**построение расписания экзаменов с конфликтами студентов.**

Основное представление решения — вектор временных слотов.

Необходимо построить расписание экзаменов таким образом, чтобы студенты не должны были сдавать два экзамена одновременно.

В работе используются:

```text
30 экзаменов
120 студентов
12 временных слотов
6 дней
2 сессии в день
```

Синтетические данные генерируются с фиксированным:

```text
seed = 20261019
```

Полученный набор содержит:

```text
230 конфликтующих пар экзаменов
```

---

## 2. Представление особи

Особь представляет собой целочисленный вектор:

```text
x = (x1, x2, ..., x30)
```

где:

```text
x_i ∈ {0, 1, ..., 11}
```

Значение `x_i` определяет временной слот экзамена `i`.

Например:

```text
x = [2, 5, 0, 4, ...]
```

означает:

```text
экзамен 1 -> слот 3
экзамен 2 -> слот 6
экзамен 3 -> слот 1
экзамен 4 -> слот 5
```

Генотип и фенотип практически совпадают.

Фенотипом является человекочитаемое расписание, содержащее день, сессию и название экзамена.

---

## 3. Входные данные

Используются три файла.

```text
data/exams.csv
data/enrollments.csv
data/conflicts.csv
```

`exams.csv` содержит список экзаменов.

`enrollments.csv` содержит информацию о том, какие экзамены сдаёт каждый студент.

На основе этих данных формируются конфликтующие пары.

Если один студент сдаёт экзамены `A` и `B`, то между ними существует конфликт:

```text
A != B по временному слоту
```

В `conflicts.csv` также сохраняется число студентов, одновременно записанных на соответствующую пару экзаменов.

---

## 4. Ограничения

### 4.1. Жёсткое ограничение

Два экзамена, имеющие общих студентов, не должны проводиться одновременно.

Для каждой конфликтующей пары:

```text
slot[A] != slot[B]
```

Нарушение этого правила делает расписание недопустимым.

---

## 5. Мягкие ограничения

Кроме отсутствия одновременных экзаменов желательно уменьшить неудобство расписания.

Используются два мягких критерия.

### 5.1. Два экзамена одного студента в день

Если конфликтующие экзамены назначены в разные временные слоты, но в один день, это не является жёстким нарушением.

Однако такое расписание менее удобно.

Подсчитывается:

```text
same_day_students
```

— количество студентов, для которых два экзамена попадают на один день.

### 5.2. Число временных слотов

Дополнительно используется небольшой штраф за число реально занятых слотов:

```text
used_slots
```

Это позволяет не растягивать расписание без необходимости.

Мягкая целевая функция:

```text
soft_penalty =
    same_day_students
    + 0.5 * used_slots
```

Необходимо минимизировать её значение.

---

## 6. Обработка жёстких нарушений

Для penalty-метода полная оценка имеет вид:

```text
score =
    1000 * conflicting_students
    + soft_penalty
```

где:

```text
conflicting_students
```

— число студентов, непосредственно затронутых одновременными экзаменами.

Большой коэффициент `1000` гарантирует, что устранение жёстких нарушений важнее небольшого улучшения мягкого критерия.

---

## 7. Начальная популяция

Начальная популяция формируется специализированным конструктивным алгоритмом.

В первую очередь рассматриваются экзамены с наибольшим количеством конфликтующих экзаменов.

Для каждого экзамена выбирается допустимый временной слот.

Если несколько вариантов допустимы, предпочтение отдаётся слотам, уменьшающим мягкий штраф.

Для разнообразия добавляется небольшая случайная составляющая.

Обе сравниваемые схемы получают допустимую начальную популяцию одного типа.

Это позволяет сравнивать именно дальнейшие способы обработки ограничений.

## 9. Селекция

Используется турнирная селекция.

Случайным образом выбираются три особи:

```text
k = 3
```

Родителем становится особь с минимальным `score`.

Турнирная селекция не требует преобразования целевой функции в вероятности.

---

## 10. Кроссовер

Реализованы два варианта.

### 10.1. Равномерный crossover

Для каждого экзамена независимо выбирается временной слот одного из родителей.

Это позволяет смешивать расписания по отдельным экзаменам.

### 10.2. Одноточечный crossover

Выбирается случайная позиция:

```text
p
```

Потомок получает:

```text
parent1[:p] + parent2[p:]
```

Второй потомок формируется обратным способом.

---

## 11. Мутация

Используется random-reset mutation.

Для каждого экзамена с вероятностью:

```text
0.08
```

выбирается новый временной слот, отличный от текущего.

Такой оператор естественен для вектора назначений.

---

## 12. Способы обработки ограничений

Сравниваются два подхода.

### 12.1. Repair

После crossover и mutation проверяется наличие одновременных конфликтующих экзаменов.

Если конфликт обнаружен, выбирается экзамен, участвующий в наибольшем количестве текущих нарушений.

Он переносится в другой слот.

При выборе нового слота учитываются:

```text
жёсткие конфликты
мягкий штраф одного дня
число используемых слотов
```

Процесс повторяется до устранения конфликтов.

### 12.2. Penalty

Потомки не исправляются.

За нарушения увеличивается значение:

```text
score
```

Поэтому недопустимые особи имеют значительно меньшие шансы пройти селекцию.

## 17. Анализ способа обработки ограничений

Сравним:

```text
GA_repair_uniform
```

и:

```text
GA_penalty_uniform
```

Среднее значение для repair:

```text
10.55
```

Среднее для penalty:

```text
13.05
```

Так как целевая функция минимизируется, repair показал лучший результат.

Это объясняется структурой задачи.

После crossover или mutation достаточно легко получить ситуацию, когда два конфликтующих экзамена оказываются в одном слоте.

Penalty только ухудшает fitness такого решения.

Repair непосредственно использует информацию о причине недопустимости и переносит конфликтный экзамен в подходящий слот.

Таким образом, вычислительный ресурс чаще используется для улучшения уже допустимых расписаний.

## 18. Анализ кроссовера

Сравним:

```text
GA_repair_uniform
```

и:

```text
GA_repair_onepoint
```

Средние значения:

```text
uniform:   10.55
one-point: 10.875
```

Лучший результат у обоих методов:

```text
9.0
```

Однако равномерный crossover показал немного лучшее среднее значение и меньший разброс.

Для данной задачи это логично, поскольку соседние позиции хромосомы не имеют особой пространственной связи.

Например, экзамены №10 и №11 не обязаны быть связанными сильнее, чем экзамены №2 и №25.

Поэтому смысл сохранения больших непрерывных участков хромосомы при одноточечном crossover ограничен.

Равномерный crossover свободнее комбинирует хорошие назначения отдельных экзаменов.

## 23. Вывод

В лабораторной работе реализован генетический алгоритм для задачи построения расписания экзаменов с конфликтами студентов.

В качестве особи используется вектор временных слотов.

Реализованы:

```text
турнирная селекция
uniform crossover
one-point crossover
random-reset mutation
элитизм
repair
penalty
```

Проведено по 20 независимых запусков.

Эксперимент показал, что для данной задачи непосредственное восстановление допустимости `repair` эффективнее штрафного подхода.

При сравнении crossover равномерный оператор показал немного более высокое среднее качество, чем одноточечный.

Лучший полученный результат имеет:

```text
soft_penalty = 9.0
hard conflicts = 0
```

Генетический алгоритм также показал более качественные результаты, чем Greedy и RandomFeasibleSearch.

Следовательно, для сформированного экземпляра задачи использование специализированного дискретного представления, repair и эволюционного поиска позволяет получать допустимые и качественные расписания.
