# Лабораторная работа №2 — вариант 19

## Тема

**Генетический алгоритм для дискретной задачи с ограничениями.**

Индивидуальный вариант:

**Построение расписания экзаменов с конфликтами студентов.**

Основное представление решения — **вектор временных слотов**.

Ключевые части генетического алгоритма реализованы самостоятельно, без DEAP, PyGAD и других готовых библиотек эволюционной оптимизации.

## Постановка задачи

Необходимо построить расписание экзаменов таким образом, чтобы студенты, записанные одновременно на несколько дисциплин, не должны были сдавать два экзамена в один временной слот.

Используется:

```text
30 экзаменов
120 студентов
12 временных слотов
2 экзаменационные сессии в день
6 дней
```

Синтетические данные автоматически генерируются с фиксированным:

```text
seed = 20261019
```

При данных параметрах получается 230 конфликтующих пар экзаменов.

## Представление особи

Особь представляет собой вектор целых чисел длины 30:

```text
[3, 1, 8, 0, 5, 5, ...]
```

Индекс гена соответствует экзамену.

Значение гена соответствует временному слоту.

Например:

```text
chromosome[4] = 7
```

означает, что пятый экзамен назначен во временной слот №8, поскольку внутри программы нумерация начинается с нуля.

## Жёсткое ограничение

Если два экзамена имеют хотя бы одного общего студента, они не могут находиться в одном временном слоте.

То есть:

```text
slot[A] != slot[B]
```

для каждой конфликтующей пары экзаменов.

## Мягкие ограничения

Дополнительно желательно:

1. Не назначать одному студенту два экзамена в течение одного дня.
2. Не использовать без необходимости слишком большое число временных слотов.

Используется мягкий штраф:

```text
soft_penalty =
    same_day_students
    + 0.5 * used_slots
```

где:

```text
same_day_students
```

— суммарное число студентов, для которых конфликтующие экзамены назначены в разные сессии одного дня.

Чем меньше `soft_penalty`, тем лучше расписание.

## Штраф за жёсткие конфликты

При использовании penalty-подхода:

```text
score =
    1000 * conflicting_students
    + soft_penalty
```

Поэтому нарушение жёсткого ограничения значительно хуже любого улучшения мягкого критерия.

Алгоритм минимизирует `score`.

## Начальная популяция

Начальная популяция строится специализированной конструктивной процедурой.

Сначала рассматриваются экзамены с большим числом конфликтов.

Для каждого экзамена выбирается допустимый временной слот.

Обе сравниваемые схемы получают одинаковый тип допустимой начальной популяции.

Это позволяет сравнивать именно способы обработки ограничений после crossover и mutation.

## Селекция

Используется турнирная селекция:

```text
tournament_size = 3
```

Из трёх случайных особей выбирается решение с минимальным `score`.

## Кроссоверы

Реализованы два оператора.

### Uniform crossover

Для каждого экзамена независимо выбирается значение временного слота от первого или второго родителя.

### One-point crossover

Выбирается случайная точка разреза.

Первая часть потомка берётся от одного родителя, вторая — от другого.

## Мутация

Используется random-reset mutation.

Для каждого экзамена с вероятностью:

```text
0.08
```

его временной слот заменяется другим случайным слотом.

## Обработка ограничений

Реализовано два метода.

### Repair

После crossover и mutation расписание проверяется.

Если два конфликтующих экзамена оказались одновременно, один из наиболее проблемных экзаменов переносится в другой слот.

Выбирается слот с минимальным количеством возникающих нарушений.

### Penalty

Недопустимые решения не исправляются.

Вместо этого за каждого затронутого конфликтом студента добавляется большой штраф:

```text
1000
```

## Baseline

Реализовано два baseline.

### Greedy

Простая конструктивная эвристика.

Экзамены с большим количеством конфликтов назначаются первыми.

Для каждого выбирается лучший допустимый временной слот.

### RandomFeasibleSearch

Создаёт независимые допустимые расписания без эволюции.

Для честного сравнения используется тот же бюджет оценок, что и для одного запуска ГА:

```text
population_size * (generations + 1)
```

То есть:

```text
30 * 61 = 1830
```

расписаний на один запуск.

RandomFeasibleSearch также выполняется 20 раз.
