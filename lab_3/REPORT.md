# Отчёт по лабораторной работе №3

## 1. Постановка задачи

Индивидуальный вариант:

```text
V = 19
```

Трек:

```text
A — многокритериальная эволюционная оптимизация
```

Задача:

**управление светофором в симуляции.**

Необходимо минимизировать три критерия:

```text
среднюю задержку автомобилей;
длину очереди;
число остановок.
```

Для решения задачи реализован алгоритм NSGA-II.

---

## 2. Модель перекрёстка

Рассматривается один перекрёсток с двумя конфликтующими потоками:

```text
North-South
East-West
```

Одновременно зелёный сигнал может быть включён только для одного направления.

Цикл работы:

```text
NS green
-> transition
-> EW green
-> transition
```

Продолжительность переходной фазы:

```text
3 секунды
```

---

## 3. Генотип

Особь содержит два целочисленных параметра:

```text
x = (gNS, gEW)
```

где:

```text
gNS
```

— длительность зелёной фазы North-South;

```text
gEW
```

— длительность зелёной фазы East-West.

Ограничения:

```text
8 <= gNS <= 50
8 <= gEW <= 50
```

Например:

```text
(20, 13)
```

задаёт цикл:

```text
20 + 3 + 13 + 3 = 39 секунд
```

---

## 4. Модель входного потока

Продолжительность одной симуляции:

```text
600 секунд
```

Для каждого временного шага генерируется факт прибытия автомобиля.

Для направления North-South:

```text
P(arrival) = 0.35
```

Для направления East-West:

```text
P(arrival) = 0.25
```

Используется фиксированный:

```text
scenario_seed = 31919
```

Поэтому все алгоритмы оцениваются на одном и том же входном потоке.

Это исключает влияние различных случайных транспортных сценариев на сравнение алгоритмов.

---

## 5. Первый критерий — средняя задержка

На каждом шаге подсчитывается количество автомобилей, оставшихся в очередях.

Каждый автомобиль, оставшийся в очереди на одну секунду, добавляет одну единицу к суммарному времени ожидания.

Средняя задержка:

```text
f1 =
total_waiting_time
/
total_arrivals
```

Критерий минимизируется.

---

## 6. Второй критерий — длина очереди

В качестве характеристики очереди используется:

```text
maximum_queue
```

то есть максимальное суммарное число автомобилей, одновременно находившихся в очередях обоих направлений.

Критерий:

```text
f2 = max_queue
```

минимизируется.

Использование максимальной, а не средней очереди позволяет оценить пиковую перегрузку перекрёстка.

Кроме того, средняя очередь в такой модели тесно связана со средней задержкой, поэтому её использование давало бы практически дублирующий критерий.

---

## 7. Третий критерий — число остановок

Автомобиль считается остановившимся, если при прибытии:

```text
горит запрещающий сигнал
```

либо:

```text
в данном направлении уже имеется очередь.
```

Критерий:

```text
f3 = stops
```

минимизируется.

---

## 8. Противоречивость критериев

Увеличение длительности зелёной фазы позволяет некоторому направлению пропускать больше автомобилей без переключений.

Это может уменьшить число остановок данного потока.

Однако слишком длительная фаза одного направления увеличивает очередь и задержку другого направления.

Следовательно, невозможно в общем случае получить одно решение, одновременно оптимальное по всем критериям.

Необходимо искать набор компромиссных решений.

---

## 9. Доминирование Парето

Решение `x` доминирует `y`, если:

```text
f_i(x) <= f_i(y)
```

для всех критериев и хотя бы по одному критерию:

```text
f_j(x) < f_j(y)
```

Если решение не доминируется ни одним другим решением, оно считается недоминируемым.

Набор таких решений образует фронт Парето.


Готовая реализация NSGA-II не используется.

---

## 11. Недоминируемая сортировка

Каждая особь получает Pareto-rank.

Первый фронт:

```text
rank = 0
```

содержит решения, не доминируемые никакими другими особями.

После их исключения определяется следующий фронт:

```text
rank = 1
```

и процесс повторяется.

При отборе меньший rank является предпочтительным.

---

## 12. Crowding distance

Одного Pareto-rank недостаточно, поскольку необходимо сохранять разнообразие решений.

Для каждого фронта рассчитывается crowding distance.

Чем больше crowding distance, тем менее плотно окружено решение соседними решениями.

При одинаковом rank предпочтение отдаётся большей crowding distance.

Такой механизм позволяет распределять популяцию вдоль фронта Парето.

---

## 13. Селекция

Используется бинарный турнир.

Случайно выбираются две особи.

Сначала сравнивается:

```text
Pareto rank
```

Если ранги одинаковы, сравнивается:

```text
crowding distance
```

---

## 14. Кроссовер

Для каждого параметра родителей случайно выбирается:

```text
alpha ∈ [-0.25, 1.25]
```

После чего:

```text
child1 =
alpha * parent1
+
(1-alpha) * parent2
```

и аналогично формируется второй потомок.

Вероятность crossover:

```text
0.90
```

После оператора значение ограничивается диапазоном:

```text
[8, 50]
```

---

## 15. Мутация

Используется гауссовская мутация.

Для каждого параметра независимо с вероятностью:

```text
0.25
```

выполняется:

```text
g = g + N(0, 5)
```

После мутации значение ограничивается допустимым диапазоном.

## 21. Weighted Sum

Для сравнения реализован второй алгоритм, использующий обычный генетический поиск и скалярную функцию:

```text
score =
w1 * delay / scale1
+
w2 * queue / scale2
+
w3 * stops / scale3
```

Используются примерно равные веса:

```text
w1 = 1/3
w2 = 1/3
w3 = 1/3
```

Нормализующие масштабы:

```text
delay = 30
queue = 10
stops = 200
```

Без нормализации число остановок имело бы гораздо больший численный масштаб и искусственно доминировало бы в агрегированной функции.

## 23. Сравнение NSGA-II и Weighted Sum

Weighted Sum вернул одно конкретное компромиссное решение.

NSGA-II сформировал набор из:

```text
37 недоминируемых режимов
```

В частности, NSGA-II позволяет увидеть крайне различные варианты.

Например:

```text
green_ns=16, green_ew=11
```

минимизирует задержку.

В то же время:

```text
green_ns=50, green_ew=8
```

уменьшает число остановок с 331 до 228, но резко увеличивает задержку.

Weighted Sum скрывает эту структуру компромиссов внутри одного коэффициента.

Кроме того, результат Weighted Sum зависит от выбранных весов и способов нормализации.

NSGA-II позволяет сначала получить множество допустимых компромиссов, а уже затем принимать предметное решение.

## 27. Вывод

В лабораторной работе реализована многокритериальная оптимизация режима работы светофора.

В отличие от предыдущих лабораторных работ, алгоритм не сводит задачу к единственной целевой функции.

Реализованы новые механизмы:

```text
Pareto dominance;
non-dominated sorting;
crowding distance;
environmental selection.
```

Эксперимент показал наличие явного конфликта между критериями.

Минимизация числа остановок может приводить к значительному увеличению задержки и максимальной очереди.

Поэтому одного универсально лучшего режима светофора не существует.

NSGA-II позволяет получить фронт Парето, представляющий различные компромиссы.

Сравнение с Weighted Sum показывает, что агрегированный критерий способен найти конкретный компромисс, но не предоставляет пользователю полного набора альтернатив.

Таким образом, для поставленной многокритериальной задачи NSGA-II является более информативным подходом.
