# Лабораторная работа №3

## Вариант 19 — управление светофором в симуляции

Трек A — многокритериальная эволюционная оптимизация.

В работе самостоятельно реализуется алгоритм NSGA-II для поиска набора режимов работы светофора, представляющих различные компромиссы между несколькими критериями качества.

## Постановка задачи

Моделируется один перекрёсток с двумя конфликтующими направлениями движения:

```text
North-South
East-West
```

Светофор работает циклически:

```text
NS green
-> transition
-> EW green
-> transition
```

Особь содержит два параметра:

```text
[green_ns, green_ew]
```

где:

```text
green_ns
```

— длительность зелёной фазы направления North-South;

```text
green_ew
```

— длительность зелёной фазы East-West.

Диапазон каждого параметра:

```text
8 <= green <= 50 секунд
```

## Критерии оптимизации

Все критерии минимизируются.

### Средняя задержка

Оценивается суммарное время ожидания автомобилей в очереди относительно общего числа прибывших автомобилей.

```text
average_delay =
total_waiting_time / total_arrivals
```

### Максимальная длина очереди

Используется максимальное суммарное количество машин, одновременно ожидавших проезда через перекрёсток:

```text
max_queue
```

Именно максимальная, а не средняя очередь используется потому, что средняя очередь и средняя задержка в такой модели сильно коррелируют и фактически дают почти одинаковые критерии.

### Число остановок

Автомобиль считается остановившимся, если при его прибытии:

```text
горит запрещающий сигнал
```

или:

```text
перед автомобилем уже существует очередь
```

Минимизируется общее число таких автомобилей.

## Сценарий движения

Используется фиксированный сценарий продолжительностью:

```text
600 секунд
```

Вероятность появления нового автомобиля за одну секунду:

```text
North-South = 0.35
East-West   = 0.25
```

Seed сценария:

```text
31919
```

Один и тот же сценарий используется для всех особей и всех алгоритмов.

Это необходимо для честного сравнения.

## Представление особи

Пример:

```text
[20, 13]
```

означает:

```text
NS green = 20 секунд
EW green = 13 секунд
```

При переходной фазе:

```text
3 секунды
```

полный цикл составляет:

```text
20 + 3 + 13 + 3 = 39 секунд
```

## NSGA-II

Ключевые части NSGA-II реализованы самостоятельно.

Используются:

```text
Pareto dominance
non-dominated sorting
crowding distance
binary tournament
environmental selection
elitism
```

Готовая реализация NSGA-II из внешней библиотеки не используется.

## Доминирование Парето

Решение A доминирует B, если:

```text
A не хуже B по всем критериям
```

и:

```text
A строго лучше B хотя бы по одному критерию
```

Недоминируемые решения формируют фронт Парето.

## Crowding distance

Внутри одного Pareto-front необходимо сохранять разнообразие решений.

Для этого используется crowding distance.

Решения, расположенные в менее плотной области пространства критериев, получают преимущество при отборе.

## Weighted Sum

Для сравнения дополнительно реализован обычный генетический алгоритм с агрегированной функцией:

```text
score =
w1 * delay / scale1
+
w2 * queue / scale2
+
w3 * stops / scale3
```

Используются одинаковые веса:

```text
w1 ≈ w2 ≈ w3 ≈ 1/3
```

Масштабирование необходимо, потому что критерии измеряются в разных единицах.

Weighted Sum также выполняется:

```text
20 раз
```

с тем же размером популяции и тем же числом поколений.

## Почему NSGA-II предпочтительнее

Weighted Sum возвращает решение, соответствующее заранее выбранным весам.

NSGA-II не требует заранее выбирать одно конкретное соотношение критериев.

В результате пользователь получает набор компромиссных решений и может выбирать режим светофора уже после выполнения оптимизации.
